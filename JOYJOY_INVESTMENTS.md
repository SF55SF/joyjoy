# JoyJoy: объекты и инвестиционные проекты

Новый кабинет: `/admin/joyjoy/`. В старом `/admin/` добавлена ссылка; прежние офисы и API сохранены.

Объявления хранятся в `src/content/properties/<slug>.json`. Каталог, страницы и карта читают их через `src/data/listings.ts`. При переносе сохранены данные CMWP и существующие адреса страниц. Переводы EN/UZ можно переопределять в новом кабинете; старые переводы остаются запасным вариантом.

## Подключение сохранения

Сохранение работает на Cloudflare Pages с Pages Functions, не в обычном Astro preview. Существующие `ADMIN_USERS` и `SESSION_SECRET` используются без изменения. Для нового кабинета задайте серверный секрет `JOYJOY_GITHUB_TOKEN` с Contents: read/write только к SF55SF/joyjoy. Если он не задан, используется существующий GITHUB_TOKEN: его права тоже должны включать JoyJoy.

По умолчанию новый API работает строго с SF55SF/joyjoy, main. Старый GITHUB_REPO, который мог указывать на Trilliant, им не используется. Необязательные JOYJOY_GITHUB_REPO / JOYJOY_GITHUB_BRANCH должны быть SF55SF/joyjoy и main. Токен никогда не вводится в браузере и не попадает в клиентский JavaScript.

Cloudflare Pages должен собирать эту ветку командой `npm run build` и публиковать каталог `dist` после GitHub-коммита. Кабинет подтверждает сохранение коммита, а не завершение публикации. При ошибке сборки опубликованная версия остаётся прежней.

Проверка конфликтов использует GitHub SHA: сохранение поверх чужой версии отклоняется. Неизвестные верхнеуровневые поля сохраняются. Новые объекты создаются неопубликованными; существующие slug не переименовываются.

## Первая модель

1. Откройте объект в новом кабинете. Проверьте данные, фотографии, координаты и переводы.
2. Введите все числовые параметры модели в USD. Пустое поле означает неизвестное значение; отсутствие затрат нужно явно указать числом 0. Сдаваемая площадь задаётся отдельно от общей.
3. Укажите основание ставки: допущение, предложение или договор, дату данных и источник/условия. В годовые расходы включите применимые налоги, обслуживание и резервы.
4. Включите «Публиковать исходные параметры модели» и «В инвестиционных проектах», затем «Объект опубликован».
5. Сохраните. После успешной сборки объект появится в `/projects/`, `/en/projects/` и `/uz/projects/`. Он может одновременно остаться в каталоге недвижимости.

В исходном патче модели CMWP не заполнены: неподтверждённых ставок аренды нет. Публичный калькулятор на странице объекта позволяет посетителю считать свой сценарий без сохранения параметров на сервере.

## Границы расчёта

Постоянные ставка, заполняемость и расходы с первого года. Все вложения = покупка + сделка + ремонт + прочие. Годовой арендный доход = сдаваемая площадь × месячная ставка × 12 × заполняемость / 100. Доход после расходов = аренда − годовые расходы. Доходность считается на все вложения, не только цену объекта. Простая окупаемость = все вложения / положительный годовой доход после расходов. При нулевом или отрицательном доходе срока окупаемости нет.

Кредит, период ремонта, постепенное заполнение, рост ставок, перепродажа и дисконтирование в эту версию не входят. Результат не называется IRR или cap rate. Это расчёт заданного сценария, а не обещание дохода.

`node scripts/joyjoy-investment-check.mjs` проверяет формулы, пограничные случаи, данные и маршруты после сборки. Методология дизайна: Unslop by Damir Sokolovsky (@heydamir), CC BY 4.0, https://github.com/heydamir/unslop.
